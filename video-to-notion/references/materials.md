# 原始材料保存与复用

## 保存位置

继续使用既有 `~/.local/skill-state/video-to-notion/data/<任务目录>/`，新任务目录和 task_id 采用 `YYYYMMDD-HHMMSS-<来源标识>`（真实本地创建时间），同秒同来源冲突再加随机后缀；例如 `20261015-203414-BV1JQhz6fE1x`。来源标识用已确认的视频 ID，本地视频无平台 ID 时用安全文件名或可确认的稳定标识。不得按标题合并不同来源；重跑先查记录，已有任务继续使用原目录，不重命名旧目录、不迁移历史索引。批次名使用实际时间加随机后缀，创建前确认不存在。

| 路径 | 内容与处理方式 |
| --- | --- |
| `sources/<提取批次>/subtitles/` | 下载/用户提供/内嵌提取的字幕原文件，保留格式、语言与时间轴，不去重、不翻译、不校订 |
| `sources/<提取批次>/asr/` | 工具原始带时间戳输出（例如 SenseVoice SRT；旧任务可能为 Whisper JSON）；保存所有本次已生成的原始结果，不只留下纯文本摘要 |
| `sources/<提取批次>/**/*.readable.json` | 必要时另存的 UTF-8 可读视图；中文直显并缩进，与原 JSON 数据等价，不覆盖原文件 |
| `sources/<提取批次>/images/` | 已确认的视频封面与用户要求的正文图表；record 区分用途、来源、时间点（封面无时间点则不编造），index.sources 关联本目录 |
| `derived/<结果批次>/` | 清洗稿、校订稿、合并时间轴、定向总结、问答和后续文章；每次新建 |
| `article.md` | 首次文章，存在时不覆盖 |
| `record.md` | 材料清单、覆盖与完整性、各次加工目标和结果路径、Notion 映射 |

原始字幕直接下载到新建的 `sources/` 批次；用户提供的字幕复制一份，不移动/修改用户文件。ASR 输出目录直接指向新批次；已有输出绝不能被重试覆盖。截图若作为文章证据长期引用也保存到 `sources/`，临时截图和媒体可留缓存。默认不永久复制整个视频/音频，如需要以后回听且源链接可能失效，可说明保留媒体的空间需求由用户决定。

按 [提取参考](extraction.md) 检查文本可读性；JSON 视图保留全部数据与时间戳，记录原文件/视图关系，向用户优先提供可读入口。它不是校订稿，语音识别错词仍保留。

## 记录与完整性

获取前先写 `record.md` 的任务条目为 `in_progress`，获取后核对文件存在、非空及时间覆盖再更新。逐个材料记录：来源 URL/平台视频及分 P 标识或本地来源；人工/平台自动/ASR/内嵌/用户提供；语言；视频时长与请求范围；实际覆盖区间、分段偏移与缺口；提取时间；工具和版本；ASR 模型名及可确认的版本（无法确认写未知）；相对文件路径；状态 `complete`、`partial` 或 `failed` 及原因。不记录 cookie、授权 header、token 或完整私密下载器响应。

`complete` 表示请求范围的处理完成，不表示转录绝对准确。分段转录保留每段原始文件与起点；换算为全片时间轴的合并稿另存 `derived/`。无法输出时间戳时明确能力不足，不伪造时间轴；保留已取得的文本并标注该限制。

中断/失败后保留已存在的部分文件，标记 `partial` 和已知缺口；若工具未生成任何结果，记录 `failed`，不能声称已保存原文。进程异常退出留下 `in_progress` 时，恢复先核对材料，不能默认完成。恢复只补缺失区间且用新批次；保存不可写时先报告并解决存储位置，不能继续生成后丢弃唯一转录。

不把原始材料存为缓存。清理只针对明确的 `cache/` 路径，排除 `data/` 与 `history/`。旧任务只有文章没有字幕时如实说明；查找其记录指向的旧缓存，如仍有原字幕可复制到长期目录后验证，不删除旧文件、不自动迁移整批任务。无法找回才在已授权范围内补取或转录。

## 当前状态与执行历史

record.md 顶部维护一个“当前状态”区，只有这里代表最新状态；后面“执行历史”按真实时间追加事件。创建时填进行中，完成/失败/暂停交付前重新读取并更新顶部，不只在末尾追加结果。已有记录出现冲突时先核实实际文件/页面结果再修正当前区，保留旧记录为历史，不把后来状态追写为当时已经完成。

当前区最少包含：task_id/run_id、更新时间、总体状态、材料覆盖、文章、Notion 写入、Notion 回读及必要未决项。四项分别写事实：

| 阶段 | 示例状态及含义 |
| --- | --- |
| 材料覆盖 | 已核对完整 / 已确认缺段 / 边界未核实，附实际范围；完整不等于逐字准确 |
| 文章 | 未开始 / 进行中 / 已生成，附实际相对路径 |
| Notion 写入 | 未要求 / 待写入 / 已写入 / 失败 / 结果不明 |
| Notion 回读 | 未要求 / 未核验 / 已核验 / 部分核验，写明实际检查范围 |

总体 index 状态仍使用现有枚举；所有本次要求阶段完成且无未决范围才 complete，部分完成或覆盖尚待核实时可 partial，并说明它不等于“确认漏转录”。文章和 Notion 已完成仍单独报告成功，不能因覆盖未知说整项完全失败。结束先更新 record 当前区，再按实际状态更新 index；任一写入失败报告未同步，二者不是原子事务，保留历史和待重试条目。

对照媒体时长、请求范围和最后一段时间戳检查边界，但最后时间戳早于音频终点只证明该区间没有 ASR 输出。必要时仅回听/检查未确认尾段，或针对尾段重试转录；不默认重跑整段，不引入全片密集画面核验。没有核对到声音就保留未知，不能称静音；确认有遗漏语音才记缺段并处理。字幕/ASR 标记、静音、音乐与不能识别的语音需按实际证据区分。

## 再次加工

1. 按任务 ID/来源确认已有材料及覆盖，读取原始材料与必要派生稿。材料充分时不再下载或转录。
2. 用户给出目标就直接执行；未给新目标仍采用忠实整理。若问题涉及未覆盖时间或未保存画面，说明缺项并只补必要材料。
3. 新建 `derived/<结果批次>/`，保存目标、依据材料路径和结果；校订疑似错词须留下原词、建议词与依据，不能覆盖 `sources/`。
4. 用户要求写 Notion 时遵循 Notion 写入与重复处理规则；原字幕和 ASR 默认仅本地保存，输出文章不得暴露本地私有路径。用户禁止本地保存时不创建这些文件，并明确不能保证跨会话复用。

## 视频与目录索引

`data/index.json` 为 UTF-8 缩进 JSON，顶层 `schema_version: 1`、`runs: []`。一项是一批处理记录；同一视频复用 `task_id` 和 `task_dir`，每次处理/重试/复用材料生成新的 `run_id`，不覆盖已结束的旧批次。多个分 P 分别记录来源 part；不能按标题认定相同视频。

开始前核实来源、实际加载 SKILL.md 的 metadata.version，读取真实带时区时间；写 record 后注册 in_progress。完成请求范围（包括本次要求的 Notion 保存）并核实结果后再标 complete；部分材料或阶段成功用 partial，完全失败用 failed，并填实际结束时间。失败原因和 Notion 映射保留在 record，不用索引替代完整记录。复用也用 mode=reuse 新建批次；sources 指向实际复用路径，不重复提取。异常留下 in_progress 时先核对 record，不能默认完成。

Agent 先用文件编辑工具生成本批次条目 JSON（放任务目录的独立批次文件，如 `index-entry-<run_id>.json`），再调用包内脚本。以下仅示例，时间与版本不可原样套用：

```json
{
  "task_id": "20261015-120000-abc",
  "run_id": "run_unique",
  "title": "示例视频",
  "source": {
    "platform": "youtube",
    "url": "https://www.youtube.com/watch?v=abc",
    "local_path": null,
    "video_id": "abc",
    "part": null
  },
  "started_at": "2026-10-15T12:00:00+08:00",
  "ended_at": null,
  "status": "in_progress",
  "mode": "extract",
  "task_dir": "20261015-120000-abc",
  "paths": {
    "sources": [],
    "derived": [],
    "article": null,
    "record": "20261015-120000-abc/record.md"
  },
  "skill_version": "0.4.0"
}
```

```bash
uv run /实际安装目录/video-to-notion/scripts/task_index.py --data-dir /实际状态目录/video-to-notion/data --entry /实际任务目录/index-entry-本批次.json
```

- 所有 task_dir/paths 值相对 data 根目录；来源 local_path 是原始媒体位置，允许绝对路径，它不是搬迁后的数据位置。来源 platform、video_id、part、title 不知道就 null；本地来源 url 为 null。外部交付文章的路径不强塞进相对路径，article 留 null，在 record 说明用户指定位置。
- URL 只保留识别视频所需的 v/p 和必要 t/start；去掉凭据、签名、跟踪参数及 fragment，再核对仍指向同一视频。token 在路径或其他非参数位置时也不得收录，使用可确认的无敏感规范链接，否则 url=null 并在 record 解释。不复制完整下载器响应。
- 新建批次开始 sources/derived 为空，只登记实际建立/复用且已核对的位置。完成或失败时写完整更新条目；不要把尚未生成的文章记录为已存在。
- 脚本锁内重新读取、验证并原子替换，不用 Agent 手工整份重写索引。相同条目可重复执行，不重复追加；不同批次会保留。已结束批次不可改写，后续处理用新 run_id。未知 schema、重复键、坏 JSON、越界路径停止且保留原文件。索引失败需明确报告并保留条目文件；修复后可重试，不声称已登记。record 与索引不是原子事务，更新中断时对照 record 核实后补登记。
- 锁超时不自动删锁；确认写入进程已经结束后才能处理遗留 `.index.lock`。仅保证协作脚本的并发写入，不保护其他手工写索引的程序；原子替换不等于完整磁盘故障恢复或备份。
- 首次遇到旧任务，仅从明确给出的 record 和材料核实后 mode=backfill 补录；未知处理时间、版本为 null，不拿当前版本冒充历史版本，不从文件修改时间推测。旧任务缺元数据不阻断读取已有材料，不扫描或迁移全部个人数据。
- 用户禁止本地保存时不创建索引。索引含私人来源信息，仅本地保存，不随文章上传 Notion、不进入发布包；迁移时连同 data 整体复制。
