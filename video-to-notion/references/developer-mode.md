# 开发者模式（可选）

用于定位本 Skill 执行中的问题，正常用户无需开启；不是后台监控、自动修复或推理链导出。

## 模式选择

1. 当次明确“开启/关闭开发者模式”优先，仅对当前任务有效，不改长期默认值。
2. 没有当次开关时，检查已有 `data/settings.md` 中经用户明确要求保存的 `developer_mode: true/false`；没有可确认设置则关闭。不创建默认设置文件。
3. 只有明确“以后保持开启/以后默认关闭”才在 `~/.local/skill-state/video-to-notion/data/settings.md` 的“开发者模式”小节保存 `developer_mode` 和确认来源/时间，保留 Notion 等其他设置；已有冲突先核实，不重写整份文件。“这次关掉”不撤销长期默认开启。
4. 用户要求“不保存”优先，不写设置、诊断或反馈，简短在会话内报告并说明不能持久复用。关闭模式立即停止新增诊断，已有记录保留，不自动删除。

开始任务时简短说明是否开启、来自当次指令还是已保存默认值；不要每个步骤重复说明。只调整开关、尚无视频任务时不创建虚构任务或日志。

## 开启后做什么

在**配置完成、材料提取结束、文章完成、Notion 写入/回读结束、交付前**各做一次轻量检查，复用已有证据；失败处理后也记录实际结果。正常模式仍按原有异常后/交付前检查，不增加这些阶段诊断。

诊断保存在当前任务 `data/<任务目录>/diagnostics/<run_id>.md`，开始写入前确认文件存在则追加，不覆盖。每个事件只写：实际时间、阶段、简短决定及可核验证据、尝试/结果、执行偏差或待确认项。必要时链接本任务相对材料路径，不粘贴完整日志或字幕；没有问题可用一句结果，不强制填表。

示例：

> 提取阶段：已有覆盖请求范围的 SRT，直接复用；未运行 ASR。依据：sources/batch/subtitles/source.srt 的时间范围检查。结果：文章可继续；尾段仍待核对。

只保存结论级决定和可观察依据，**不保存私有推理链、内部思维过程或逐步隐含推演**。不记录密码、Cookie、token、完整授权 URL、无关电脑信息或完整私密对话。日志不自动上传、不同步 Notion，不进入源码或交付包；分享沿用反馈允许字段副本及内容审查。

出现有证据的改进点时按 [反馈规则](feedback.md) 查重追加，区分用户报告/Agent 观察/推测；日志存在不等于必有反馈，不凑数量。开发者模式不自动授权自改 Skill、重跑全片、重写文章或外传。

轻量检查依赖已有结果，不因开启模式自动增加截图、下载、工具调用或大规模重试。若深入排查预计明显增加 token，先说明拟做范围、增加原因和较省 token 的方案，精确成本未知就说明，再取得同意；耗时为补充，不用它替代 token 说明。写诊断失败如实报告，不宣称已保存；业务材料和诊断的结果分别说明。
