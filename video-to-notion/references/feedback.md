# 本地使用反馈与自身改进

用户指出问题、建议或值得保持的体验，或运行自查发现有具体证据的改进事项时，简短确认理解并检查 `~/.local/skill-state/video-to-notion/data/` 下已有反馈。兼容 `feedback.md` 和 `feedback/`：已有同一问题就在原记录补充；仅有一种布局就沿用；两者都有时先查同项记录，新项优先使用 `feedback.md`，不重复建账或强制迁移。都没有时才新建 `feedback/<YYYYMMDD-HHMMSS>-<随机后缀>.md`，一次反馈一文件。用户要求不记录则不保存；记录不可写时说明失败，不声称已收集。不为普通任务预建反馈目录。

使用真实本地时间（带时区），Markdown frontmatter 包含 `schema_version: 1`、`id`、`skill: video-to-notion`、`created`、`kind: problem | positive | suggestion`（选一项）、`status: recorded`。正文用简短段落记录用户原意、观察事实与脱敏证据、期望或应保持的行为、关联任务及后续变更/验证。区分用户报告、Agent 推测与实际复现；保留用户原意，不把语音错字当成需求。

状态只在有依据时更新：`recorded`（已记录）、`verified`（已核实）、`planned`（已安排）、`implemented`（已修改）、`validated`（已验证）、`closed`（已关闭并说明原因）。修复后记录具体版本或变更、验证结果和仍未验证的情况；记录不等于解决。正面体验也作为之后改动的保留要求。

反馈默认仅本地，开发者不会自动收到。用户明确要求分享时按下方允许清单生成预览；由用户自行分享或另行明确授权发送；不自动上传，不将视频全文、凭据或私密账号信息附带出去。开发者在源码改进时可引用脱敏反馈写入维护记录，维护记录不入 Skill 包。本流程不依赖安装其他 Skill。

已有单文件反馈保留其编号、日期和状态格式，不为套用新格式重写历史。只补充真实证据；用户报告“已实施”时保留其说法并注明来源，未独立验证不得改称已验证。

## 运行中的主动自查

异常处理结束后和交付前各做一次轻量自查；只检查本任务已经观察到的行为、结果和已有规则，不为了找问题扩大扫描或反复调用工具。没有具体问题就不建记录，不凑建议或评分。

有可复核证据且值得改进时，先查已有同项反馈并追加本次证据/关联任务，避免按每次运行重复建条。记录“用户报告”“Agent 观察”“待证实推测”的来源，写明事实、影响、建议和未验证范围；执行没有遵循已有规则时如实记录执行偏差，不一概称 Skill 规则缺失。一般网络、登录、沙箱或设备限制不自动算缺陷；只有具体处理流程可改进且有证据时记录相关问题，不猜底层错误原因。发现原判断有误时追加更正与依据，不删除原历史或坚持错误结论。

结束时简短告知新增/补充的反馈编号及状态；保存失败就报告未记录。用户要求不保存时遵循。主动记录不自动授权修改 Skill、修复旧文章、更新全局配置或上传反馈。

## 本地隐私与分享副本

本地反馈也不写密码、token、Cookie、授权 header 或密钥；证据先选必要摘要，不能因为“只在本机”就复制凭据。只使用当前问题已有且必要的环境信息，不遍历收集本机配置、设备标识、所有依赖或无关文件。

跨电脑分享时，新建独立副本，原记录不变；不能默认复制整条本地记录再用黑名单正则删敏感词，也不能声称正则保证完全脱敏。**先按以下允许字段选取，再逐段审查字段内文字**：

| 允许字段 | 内容边界 |
| --- | --- |
| 反馈 ID（可选） | 非敏感编号，不含设备标识或本机任务路径 |
| 问题 | 必要的简短问题描述与证据来源类型 |
| 复现步骤 | 最少必要步骤，路径用占位符、媒体用虚构示例，不含真实私人来源 |
| 预期 / 实际 | 可验证的差异，不把推测写成事实 |
| 发生 / 修复版本 | 可核实的 Skill 版本；未知 null，不以当前版本回填 |
| 必要环境（可选） | 只有定位该问题确需时才列 OS、相关依赖版本；不附用户名或设备身份 |
| 最少脱敏证据 | 用自造示例或必要短摘录保留复现信息，逐段检查用户定制及私人内容 |

默认不包含用户名、绝对路径、设备 ID、私人视频 URL、Notion URL、原始字幕、完整日志、完整 references、其他附件、任务目录、安装身份指纹/哈希。本地记录中的 installation、task_id/run_id、来源链接等不会因已有字段就自动进入分享副本。确需引用 references 时只摘与问题直接相关的最小片段，检查其中本地定制是否含私人信息；不能直接打包 references 目录。

可用以下轻量模板；无必要的可选项删除，不为了填表采集信息：

```markdown
# 反馈分享预览
- 反馈 ID：<可选的非敏感编号>
- 问题：<必要摘要；注明用户报告/Agent 观察/待证实推测>
- 发生版本：<已核实版本或 null>
- 修复版本：<已核实版本或 null>
- 必要环境：<确需时列 OS/相关依赖版本，否则删除>

## 复现步骤
<使用占位路径和虚构输入的必要步骤>

## 预期与实际
<可核实差异；保留未知和未验证边界>

## 最少脱敏证据
<短摘要、自造示例或已逐段审查的必要片段>
```

检查字段之外还要检查**字段内容**：问题标题、命令、错误片段都可能藏有路径、私人 URL 或定制内容。不能安全去除且仍保留必要含义时，说明该证据未纳入，向用户说明缺项，而不是悄悄带出原文。

生成预览并说明省略范围后，由用户自行分享，或取得针对目的地和内容的另行明确发送授权；生成副本不等于已发送。不自动上传，不附整个状态目录或原始材料，不把反馈副本混入 Skill 包。默认本地分享副本放目标状态目录 `data/feedback-exports/<唯一批次>.md`，不放源码；演练只用临时目录。

## 版本、安装身份与时间

每条反馈都保留下面这些元信息，可在现有 Markdown 条目中用字段列表表达，无需数据库。新建独立文件时也可放 frontmatter；已有单文件在对应条目内补充，不把整份文件的版本误当每条反馈的版本。

| 字段 | 记录规则 |
| --- | --- |
| `occurred_at` | 问题或体验实际发生时间，含时区；只知日期就保留日期并注明精度，未知为 null，不拿记录时间代替 |
| `recorded_at` | 本次记录的实际时间，含时区；原有 created 保留为创建时间，不改成发生时间 |
| `skill_version` | **发生时**实际使用的 Skill 版本；从当时任务记录/安装快照等可核实证据取得，并说明依据；未知为 null |
| `recorded_with_version` | **记录时**实际加载 SKILL.md 的 metadata.version；与发生时版本分开，未知为 null |
| `task_id` / `run_id` | 已确认的任务和处理批次标识；无关联或无法确认则 null，可附已有任务记录路径 |
| `installation` | 可核实的实际加载安装路径、观察时间 observed_at、SKILL.md 的 SHA-256（或明确覆盖文件清单的指纹）与 local_changes；无法核实的值为 null/unknown |

`installation.observed_at` 说明该安装证据是何时观察到的；记录时看到的安装不能冒充发生时安装。若当时快照可用，另列带明确时间的历史安装证据，不覆盖当前观察。路径只记录当前实际加载位置，不猜默认目录或凭源码位置代替；分享时去除用户名等私人路径信息。

版本号只表示发布标识，不能证明文件未被本地修改。`local_changes` 仅在与可信的同版本基线核对后填写 `modified` 或 `unmodified`，否则为 `unknown`；不能把“没看到修改记录”当无修改。单独 SKILL.md 的 SHA-256 只覆盖该文件，不能证明 references/scripts 等未改；若记录其他指纹，写明算法及覆盖清单。指纹缺失不阻断反馈记录，也不要求为反馈安装额外工具。

修复后单独追加 `fixed_in_version`（未知 null）、实际修改位置/历史记录、验证时间、方法、结果与未测项。发生版本、记录版本、修复版本不能互相覆盖；只改安装文件但未升发布版本时按实际标识记录，并用变更证据区分。修复版本存在不等于已验证。

历史条目缺信息保持缺失或明确未知；只有用户要求补录且找到可核实证据时才追加来源，不把今天的版本、路径或时间回填到过去。本规范升级不自动改写已有反馈，也不授权实施反馈中的建议。

## 发布后的自身改进

记录反馈本身不授权修改源码、安装副本或全局配置。用户明确要求修复、已确认方案或已有适用授权时，直接在本次实际加载的 `SKILL.md` 所在安装目录做必要修改；不重复索取同一许可。复杂改动先写简短 spec，放入本次 history，不混入运行指令。

发布包不依赖作者源码路径，不自动寻找仓库、同步源码或重新发布。维护者明确要求维护源码时才在指定仓库修改；不得因发现仓库就改变本次修复目标。安装路径不确定或不可写时报告实际限制，不改另一个副本冒充成功。

新建快照采用 `history/YYYYMMDD-HHMMSS/snapshot/`，同秒冲突追加唯一后缀，批次根保存 `change.md`。保留每个来源根目录内的原相对路径：`snapshot/before/installed/SKILL.md`、`snapshot/before/installed/references/extraction.md`；改后对应 `snapshot/after/installed/...`。涉及维护源码时另放 `snapshot/before/source/...` 与 `snapshot/after/source/...`，不得把不同来源同名文件编号铺平混放。

`change.md` 记录真实时间与时区、反馈编号、授权、实际来源根目录、修改前后版本（未知明确标记）、文件清单/指纹、完整安装备份或仅改动文件的范围、新文件原先不存在标记、验证及逐文件恢复方法。只保存改动文件的快照不能称完整历史版本。旧 history 的 record.md/restore.md 与映射继续有效，不重排、重命名或覆写。恢复前仍检查后来修改。

修改前读取当前文件与相关反馈，按以上布局保存受影响文件快照，在 `change.md` 写清：反馈编号、原因、授权依据、实际安装位置、文件清单、原先不存在的新文件及恢复步骤。核对快照后再修改，快照失败就停止修改。保留用户定制，不把凭据或无关个人资料纳入快照。

修改后检查指令一致性、引用可达性及相关行为，保存修改后文件快照或完整可复核差异与校验信息，将变更和验证结果关联到 history 与原反馈记录。失败或中断如实写明阶段；未验证不得称已解决。恢复前将当前文件与本次改后内容比较，不能直接用旧快照覆盖用户的新内容；本次新增文件仅在仍等于本次改后内容时才可在恢复中删除，否则先处理差异。未来新包覆盖安装时先比较这些本地改进，外部 history 保留不代表安装内修改自动合并。反馈和历史仅留在状态目录，不进入分享包。
